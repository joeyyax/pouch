Switch providers without a deploy

A domain's provider is a setting. Your code calls the same API either way.

Pauses before your provider does

A domain holds its queue at half the bounce or complaint rate SES reviews accounts at, until you release it.

Bodies you can really delete

Each message is encrypted with its own key. Retention shreds the key, and Pouch can't open the body again.

The record stays yours

Every send is a row in your Postgres, kept past your provider's retention. Export CSV, NDJSON or .eml any time.

Addresses your code creates

Inbound addresses with an expiry that code can read, reply from and forward.

Built in for agents

An MCP server that sends, reads the log and waits for mail to arrive.

Also Passkeys and sign-in links · DMARC reports · blocklist checks · signed webhooks · SMTP · TypeScript SDK · push alerts when a check fails

How Pouch works

Your provider delivers

Pouch sends through your Amazon SES, Mailpace or Cloudflare account with your credentials. The domain and its reputation stay with the provider.

Pouch keeps the record

One API for every app and one dashboard that shows every message, its state and why.

No lock-in

Your sending records point at your provider, never at Pouch. Export the log and the mail any time; leaving is a code change.
